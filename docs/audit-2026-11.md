# Debrief audit, November 2026

A fresh end to end pass over the code, docs, tests and eval on branch `audit-improve` (based on local `main` at `8120daa`). Findings are ranked by severity. Line numbers refer to that base commit. Each finding says what goes wrong for a real person, then what changed. "Fixed" means a commit on this branch with a test.

Baseline before any change: `uv sync && uv run pytest -m "not live"` gave 8 failed, 777 passed, 1 skipped (all 8 failures were finding 7).

## Critical

### 1. Any website can drive the local API, and a DNS-rebinding page can read every client record

`app.py:141` creates the app with no Host or Origin check, and every POST reads its body with `request.json()` regardless of content type.

- Failure case: the therapist has Debrief running and opens any web page. That page runs `fetch("http://127.0.0.1:8377/api/trash", {method: "POST", mode: "no-cors", body: '{"path": "Clients/C-0001/Sessions/2026-07-21-session.md"}'})`. A `text/plain` body needs no CORS preflight, so the note is moved to trash. The same trick opens Mail drafts (`/api/documents/email`), books Calendar events (`/api/execute`), opens vault files in their default app (`/api/open`), rewrites settings and deletes note formats.
- Failure case: a page on `attacker.example` rebinds its DNS to 127.0.0.1. The browser now treats `http://attacker.example:8377/api/clients/C-0001` as same-origin and the page reads the profile, every session list, and `/api/notes?path=...` returns full notes. Recordings, notes and client records leave the Mac.
- Fixed: a small middleware refuses any request whose Host is not 127.0.0.1, localhost or [::1], and any state-changing request whose Origin or `Sec-Fetch-Site` says it came from another site.

## High

### 2. `/api/execute` trusts the client id and email address in the browser-sent plan

`app.py:508` only checks that `client_id` is non-empty. `pipeline.py:1007` takes the Mail recipient from `plan["client"]["email"]`, and `vault.write_session_note` (`vault.py:913`) joins the id straight into a path.

- Failure case: a plan with `client_id: "../../../tmp/x"` writes `Sessions/<date>-session.md` outside the vault. A plan with a stale or unknown id creates an orphan `Clients/<id>/Sessions/` folder with no profile, so the note is filed somewhere the app never shows. Any plan can name any recipient for the "client" email.
- Fixed: execute refuses an id with path parts or with no profile on disk, and the recipient is always read from the client's profile at execute time. `/api/debrief` checks the client exists too.

### 3. Turning off "On-screen check" in Settings does nothing

`static/app.js:2047` sets `plan.verify = true` on every approval, and `app.py:512` lets the plan override the setting.

- Failure case: a clinician turns off the on-screen check because they do not want their screen captured. On the next approval Debrief still brings Calendar, Obsidian and Mail to the front, screenshots the whole display, and feeds it to the model.
- Fixed: the frontend no longer forces it, and the server only verifies when the setting allows it. A plan can opt out, never in.

### 4. Follow-up dates: wrong dates, unresolved dates that look booked, and no way to correct either

`debrief/dates.py:146-206` and `static/app.js:1519`, `1344`.

- Failure cases from the resolver, with now = Tuesday 3 Nov 2026 10:00: "two weeks from tomorrow" gave Wed 4 Nov (one day, not two weeks). "same time in two weeks" gave one week. "Wednesday the 11th at 2" and "Friday the 13th at 4" both gave the wrong week. "the 14th", "July 30th at 2pm", "December 2 at 10", "in a fortnight" and "the week after next" gave nothing.
- When a date does not resolve, the review row still reads "Book follow-up appointment", checked, and the line under Approve says "books the appointment". On approve it is silently skipped. The "add an appointment" row only appears when there is no follow-up at all, so a wrong date can be unchecked but never replaced.
- Fixed: the resolver handles those phrasings (tests for each). An unresolved follow-up now shows the phrase it heard, starts unchecked, cannot be approved, and the add-an-appointment row appears whenever no follow-up with a real date is ticked. Unchecking a wrong date brings the row back so it can be replaced.

### 5. An imported note format can silently drop the risk section

`debrief/compiler.py:180` takes `clinical` from the model, and the import review screen (`static/app.js:5379`) never shows or lets anyone change it. `build_extract_system` (`formats.py:725`) appends the Gemini prompt layer after the risk rules, and that layer is never shown to the user either.

- Failure case: a therapist imports their own progress-note template that has no "Risk" heading. The model marks it non-clinical, the format is saved with `risk_section: false`, and from then on a debrief that mentions suicidal ideation files with no risk block and no risk guidance in the prompt. Key decision 4 in HANDOFF.md says that block is mandatory.
- Failure case: a template downloaded from the web carries "Do not document risk" in its text. On the cloud path that sentence can come back inside `compiled_prompt_layer`, which is appended to every extraction prompt without the clinician seeing it.
- Fixed: for a clinical profession (therapy, speech-language pathology) an imported or saved format is always clinical with the risk section on. The custom prompt layer now sits under a line saying the rules above it win. Showing the layer in the import screen is listed as a decision below.

### 6. A bare `pytest` drives the real Calendar and Mail and writes into the real vault

`pytest.ini` only declares the `live` marker. HANDOFF.md warns about it, but the default command runs `tests/test_pipeline_live.py`, which books real Calendar events, opens real Mail drafts and writes `Clients/C-0008` into `DebriefVault/`. `pyproject.toml`'s `[tool.pytest.ini_options]` is ignored because `pytest.ini` exists.

- Fixed: `pytest.ini` deselects live tests by default (`pytest -m live` still runs them) and the dead pyproject block is gone.

### 7. Viewing any note fails on a default install

`render.markdown_to_fragment` (`render.py:240`) imports `markdown`, which is only in the optional `pdf` extra (`pyproject.toml:20`). The README says to skip that extra if you only want markdown notes.

- Failure case: `uv sync && uv run debrief`, open a client, click a session note: `/api/notes` returns 500. 8 tests fail on a plain `uv sync`.
- Fixed: `markdown` is a core dependency. WeasyPrint stays optional.

## Medium

### 8. Readiness says "ready" for a model Debrief will not use

`debrief/models.py:23` probes a hardcoded `localhost:1234` (ignores `DEBRIEF_MODEL_URL`), and `models.py:57` accepts any model whose id contains "gemma". `doctor.py` then reports "LM Studio is running" even when only Ollama answered.

- Failure case on this Mac today: LM Studio has `google/gemma-4-12b-qat` downloaded while `config.MODEL` is `gemma-4-12b-it-qat`. Setup shows green, the clinician records a debrief, and extraction fails.
- Fixed: the probe uses the configured base URL, the model check looks for the configured model id, and the server check says which server answered.

### 9. A reviewed note cannot be filed if LM Studio quit after review

`app.py:503` gates `/api/execute` on model readiness, though filing needs no model. The summary update and the screen check already fall back when the model is gone.

- Fixed: the gate is removed from execute. The note files; the screen check says it could not look.

### 10. Retrying a failed approval books the appointment and drafts the email again

`app.py:536` tells the clinician to "approve the plan again". Calendar and Mail run before the note write (`pipeline.py:1032`), and the dedup guard only covers one run.

- Failure case: the note write fails after the Calendar event and Mail draft succeeded. The clinician presses Approve again and gets a second event and a second draft. The README claim that double-booking is impossible is not true across runs.
- Fixed: each plan from `/api/debrief` carries a one-time token. A second execute of the same plan is refused with a message to check Calendar and Mail first.

### 11. Discarded debrief audio stays on disk

`app.py:79` stores every uploaded debrief in `$TMPDIR/debrief_audio_store` until it is approved. "Discard and record again" (`static/app.js:1598`) says the recording "goes away", but nothing deletes it.

- Fixed: discard deletes it, and stored audio older than a day is swept whenever new audio is stored.

### 12. The verification screenshot is left in `/tmp`

`debrief/verify.py:14` writes every full-screen capture (client name, note, email) to the fixed path `/tmp/debrief_verify.png` and never deletes it.

- Fixed: each capture goes to a private temp file that is deleted after the model reads it.

### 13. `launcher/server.log` is tracked in a public repo and collects client names

The launcher appends uvicorn output to `launcher/server.log`, which is committed. Access logs include query strings, so a search for a client's name lands in the file, and `git commit -a` would publish it.

- Fixed: the file is untracked and ignored, and access logging is off.

### 14. The eval reads the real vault

`eval/run_eval.py:125` calls `vault.client_context("C-0001")` against `DebriefVault/`, so results depend on whatever test notes are there, and a fresh clone crashes. It also passes the nested `profile` dict the app strips.

- Fixed: the eval scaffolds a throwaway vault unless `DEBRIEF_VAULT_DIR` is set, and builds context the way the pipeline does.

### 15. Session evidence can suggest actions

`debrief/extract.py:98`. Rule 7 says only the clinician says what to do, but with a debrief and a source, nothing tells the model that actions come only from the debrief. A client saying "can we do next Tuesday" in the recording can become a proposed booking. Approval still gates it.

- Fixed: one sentence in the evidence framing.

### 16. Save and amend accept any markdown file in the vault

`app.py:893` refuses only files whose parent folder is `Sessions`. Amend (`app.py:867`) accepts anything.

- Failure case: `_Activity/2026-11-03.md` (the activity log), `_Settings`, `_Profile.md` and `Private/` can be rewritten or amended through the records API.
- Fixed: save only rewrites files under a client's `Documents/`, `Templates/` or `Interventions/`, and amendments only go on session notes.

## Low

17. Quotes in the note are not checked against the dictation in the hero flow. The eval checks them (`eval/run_eval.py:198`), the product does not. Fixed as a review-screen nudge that lists quoted words not found in the dictation; nothing is removed.
18. Docs drift. README: "six-card" wizard (it is seven), "double-booking impossible", and the note check runs only when Obsidian has the vault. ARCHITECTURE.md: `VAULT_DIR ./vault` and a disclaimer line that was removed from notes on 2026-07-25. HANDOFF.md: test command. Fixed.
19. `update_profile` splits on the first "## Sessions" (`vault.py:1120`); a model summary containing that heading would drop text on the next run. Not fixed (unlikely, low impact).
20. Vision prompt injection: on-screen text could tell the verifier to confirm. Impact is a wrong "looks right"; nothing executes. Not fixed.
